# Uchat — Корпоративный чат для сотрудников

Полнофункциональный корпоративный мессенджер с работами, событиями, комментариями, обедами и личными сообщениями в реальном времени.

---

## Требования для запуска

| Компонент | Требование |
|-----------|-----------|
| Docker + Docker Compose | Единственный поддерживаемый способ запуска всего стека |
| Браузер | Chrome, Firefox, Edge (последние версии) |
| ОС | Windows / Linux / macOS (везде, где есть Docker) |
| Порты | 8001 (приложение), 5432 (PostgreSQL, для прямого доступа к БД снаружи) |

Отдельная установка Python или PostgreSQL не нужна — оба живут внутри контейнеров.
Батники (`start.bat`, `stop.bat` и т.п.) из проекта убраны, Docker — единственный
путь запуска.

### Быстрый старт
1. Из корня проекта: `docker compose up -d --build`
2. Открыть http://localhost:8001
3. Войти под дефолтным admin (см. ниже)

При первом запуске Postgres создаёт пустую БД `workchat`, backend сам создаёт
таблицы (`init_db()`) и дефолтного администратора, если таблица `users` пуста.

Для разработки без пересборки контейнера при каждом изменении фронтенда — Vite
dev-сервер (`frontend/`, `npm run dev`, порт 3001, проксирует `/api` и `/ws` на
backend на :8001, который в этом случае можно запускать и не в Docker: `python
main.py` из `backend/`).

### Доступ с других компьютеров / из интернета
1. В локальной сети: узнайте IP-адрес компьютера (в cmd: `ipconfig`) и откройте
   `http://ВАШ_IP:8001`, убедитесь, что брандмауэр разрешает порт 8001.
2. На VPS: после `docker compose up -d --build` приложение доступно по
   `http://IP_VPS:8001`. Для постоянного показа коллегам/в продакшене
   рекомендуется:
   - сменить дефолтный пароль Postgres (`POSTGRES_PASSWORD` в
     `docker-compose.yml`, сейчас `postgres123`) перед тем как открывать порт наружу;
   - поставить обратный прокси (nginx/Caddy) с доменом и HTTPS перед портом
     8001 — тогда заработает `wss://` для WebSocket и не будет предупреждений
     браузера о незащищённом соединении;
   - при необходимости сузить `CORS_ORIGINS` (по умолчанию `*`) до конкретного домена.

### Дефолтный вход
- **Логин:** admin
- **Пароль:** admin123

> ВАЖНО: После первого входа обязательно смените пароль администратора через панель управления.

## Как устроены сессии

У приложения **нет серверных сессий или токенов** (JWT и т.п.):

- При логине (`POST /api/auth/login`) сервер просто сверяет SHA-256 хеш пароля
  и возвращает объект пользователя. Клиент сохраняет его в
  `localStorage['chat_user']` и держит там **бессрочно** — сервер не проверяет
  этот объект повторно, и разлогинить пользователя "снаружи" (например, при
  смене пароля админом) нельзя, пока клиент сам не очистит localStorage.
- Все последующие запросы и WebSocket-подключение (`/ws?user_id=...`) просто
  передают `user_id` из этого сохранённого объекта — сервер доверяет ему без
  повторной проверки пароля.
- Ежедневный сброс в 1:00 (см. «Фоновые процессы») **не разлогинивает**
  пользователей: он лишь принудительно рвёт WebSocket-соединения и на момент
  сброса помечает всех оффлайн в БД. Фронтенд переподключается автоматически
  через 3 секунды тем же `user_id` из localStorage, и статус "онлайн"
  восстанавливается — с точки зрения пользователя это незаметно.
- Выйти можно только вручную (кнопка "Выход", она чистит localStorage) или
  очисткой данных браузера.

## Роли и права

### Обычный пользователь
- Просматривать работы, события, обеды
- Создавать работы и события
- Завершать работы и события
- Отмечать важные работы/события
- Добавлять комментарии (1 на работу/событие)
- Отправлять личные сообщения
- Редактировать свои работы и события
- Изменять время окончания событий

### Администратор
Все права обычного пользователя +:
- Создавать и удалять пользователей
- Назначать права администратора другим пользователям
- Удалять любые работы и события
- Доступ к панели управления (кнопка "Админ" в сайдбаре)

> ВАЖНО: Дефолтный пользователь `admin` нельзя удалить. Это защита от потери доступа.

## Функционал подробно

### 1. Работы на сети

**Назначение:** Отслеживание текущих задач сотрудников.

**Как создать:**
1. Перейти во вкладку "Работы"
2. Ввести текст в поле "Новая работа..."
3. Нажать Enter или кнопку "+"

**Возможности:**
- **Завершение:** Кнопка ✓ рядом с работой. Показывается кто и когда завершил
- **Важные:** Кнопка ⚠ в меню действий. Важные работы отображаются выше остальных с жёлтым акцентом
- **Редактирование:** Кнопка ✏️ в меню действий. Открывается панель под карточкой, Enter сохраняет
- **Комментарий:** Кнопка 💬 в меню действий. Один комментарий на работу, новый заменяет старый
- **Копирование:** Кнопка 📋 копирует полный текст работы с метаданными
- **Удаление:** Только для администратора, кнопка X в меню действий

**Цвета карточек:**
- Зелёный фон — активная работа
- Красный фон — завершённая работа
- Жёлтый фон — важная работа

**Фильтрация:** Все / Активные / Завершённые

**Сортировка:**
1. Важные — выше всех (по времени назначения важным)
2. Активные — по дате создания (новые сверху)
3. Завершённые — по дате завершения (свежие завершённые выше)

---

### 2. События

**Назначение:** Плановые события с привязкой ко времени.

**Как создать:**
1. Перейти во вкладку "События"
2. Ввести текст в поле "Новое событие..."
3. Нажать Enter — откроется календарь для выбора даты/времени
4. Выбрать дату и время, нажать "Создать"
5. Или нажать "Без времени" для события без привязки ко времени

> ВАЖНО: Создать событие можно ТОЛЬКО выбрав дату в календаре или нажав "Без времени". Дата не может быть в прошлом.

**Статусы событий:**
- **Активное** — событие в процессе (зелёный фон)
- **Завершённое** — завершено вручную кнопкой (красный фон, надпись "Завершено")
- **Истёкшее** — автоматически завершено по времени (красный фон, надпись "Время события истекло")

**Автозавершение:**
- Проверка каждые 30 секунд
- Если текущее время >= event_time, событие автоматически становится "истёкшим"
- Важность автоматически снимается при автозавершении
- Устанавливается completed_at = текущее время

**Изменение времени:**
- Кнопка 🕐 в меню действий (только для событий с установленным временем)
- Открывается календарь для выбора нового времени
- При изменении времени статус сбрасывается на "активное"

**Прочие возможности** аналогичны работам: важные, редактирование, комментарии, копирование, удаление.

---

### 3. Личные сообщения

**Назначение:** Переписка между сотрудниками в реальном времени.

**Как начать чат:**
1. Перейти во вкладку "Сообщения" в сайдбаре
2. Выбрать пользователя из списка
3. Начать вводить сообщение

**Особенности:**
- Реалтайм доставка через WebSocket
- Синий пузырь — ваши сообщения (справа)
- Серый пузырь — сообщения собеседника (слева)
- Enter — отправить сообщение
- Shift+Enter — перенос строки
- Авто-расширение поля ввода
- Эмодзи-пикер (кнопка 😊 в поле ввода)

**Сортировка пользователей (как в мессенджере):**
1. Пользователи с сообщениями — по времени последнего сообщения (свежее выше)
2. Пользователи без сообщений — по алфавиту
3. Выбранный чат не поднимается наверх, остаётся на своём месте

**Фильтры:**
- **Все** — все пользователи
- **Непрочит.** — только с непрочитанными сообщениями
- **Онлайн** — онлайн пользователи
- **Офлайн** — оффлайн пользователи

**Отслеживание прочитанных:**
- Синяя точка с числом — количество непрочитанных сообщений
- При открытии чата сообщения помечаются как прочитанные (серверно)
- Бейджи сохраняются при обновлении страницы

---

### 4. График обедов

**Назначение:** Планирование обеденных перерывов.

**Как добавить обед:**
1. Перейти во вкладку "Обеды"
2. Выбрать сотрудника в сайдбаре
3. Выбрать дату (календарь вверху)
4. Нажать "+" напротив нужного часа (9:00–19:00)

**Особенности:**
- Сетка по часам от 9:00 до 19:00
- Один сотрудник — один обед на час
- Повторное нажатие "+" меняет время обеда
- Кнопка "×" удаляет обед
- Кнопка "Очистить все" — удаляет все обеды за выбранную дату (с подтверждением)
- Поиск по сотрудникам

---

### 5. Уведомления (бейджи)

- **Работы** — оранжевая точка при создании новой работы (только если не на вкладке "Работы")
- **События** — оранжевая точка при создании нового события (только если не на вкладке "События")
- **Сообщения** — синяя точка с числом непрочитанных сообщений

Текущая вкладка сохраняется при обновлении страницы.

---

### 6. Сайдбар

**Структура:**
- Логотип и название "Uchat" (вверху)
- Кнопка сворачивания сайдбара (←)
- Навигация: Работы, События, Обеды, Сообщения
- Список пользователей (во вкладке "Сообщения") или сотрудников (во вкладке "Обеды")
- Профиль пользователя (внизу): аватар, имя, кнопка выхода

**Сворачивание:**
- Кнопка ← рядом с логотипом сворачивает сайдбар
- При свёрнутом сайдбаре в заголовке появляется кнопка → для разворачивания
- Состояние сайдбара не сохраняется при обновлении

---

### 7. Админ-панель

**Доступ:** Кнопка "Админ" в сайдбаре (только для пользователей с правами администратора).

**Возможности:**
- **Создание пользователей:** Логин, отображаемое имя, пароль, права администратора
- **Удаление пользователей:** Кнопка удаления рядом с пользователем (кроме дефолтного admin)
- **Смена пароля:** Кнопка 🔑 рядом с пользователем, ввод нового пароля + Enter
- **Назначение админа:** Чекбокс "Админ" при создании пользователя

**Ограничения:**
- Логин должен быть уникальным
- Дефолтный пользователь `admin` защищён от удаления
- Rate limiting: 10 созданий пользователей в минуту

## Поведение при обновлении страницы

- **Авторизация** — сохраняется в localStorage, не сбрасывается
- **Текущая вкладка** — сохраняется (Работы/События/Обеды/Сообщения)
- **Выбранный чат** — сохраняется, при обновлении открывается тот же диалог
- **Бейджи работ/событий** — сохраняются, не пропадают при обновлении
- **Сайдбар** — сбрасывается в развёрнутое состояние
- **Данные** — перезагружаются с сервера

## Лимиты и ограничения

| Ресурс | Лимит | Действие при превышении |
|--------|-------|------------------------|
| Работы | Без лимита | Завершённые удаляются через 30 дней |
| События | Без лимита | Завершённые/истёкшие удаляются через 30 дней |
| Сообщения | Без лимита | Удаляются через 30 дней |
| Комментарии | 1 на работу/событие | Новый заменяет старый |
| Обеды | Без лимита | Очищаются вручную |

**Rate Limiting** (по IP, через slowapi; применён точечно — не на все эндпоинты):
- `POST /api/auth/login` — 10 попыток в минуту
- `POST /api/admin/login` — 5 попыток в минуту (отдельный, более строгий лимит)
- `POST /api/admin/users` (создание пользователя) — 10 в минуту
- Остальные эндпоинты (работы, события, обеды, сообщения, смена пароля) —
  без rate limiting

**Длина полей:**
- Логин: 1–50 символов
- Имя пользователя: 1–100 символов
- Пароль: 1–100 символов
- Текст работы/события: до 2000 символов
- Комментарий: до 1000 символов

## Фоновые процессы

| Процесс | Расписание | Описание |
|---------|-----------|----------|
| Очистка сообщений | Каждый час | Удаление сообщений старше 30 дней |
| Сброс онлайн-статусов | Ежедневно в 1:00 (время Уфы) | Все пользователи помечаются оффлайн в БД, все WebSocket разрываются. Логин НЕ сбрасывается — клиенты переподключаются автоматически через 3 сек (см. «Как устроены сессии») |
| Архивация работ | Ежедневно 6:00 | Завершённые старше 30 дней переносятся в work_logs |
| Архивация событий | Ежедневно 6:00 | Завершённые/истёкшие старше 30 дней переносятся в event_logs |
| Автозавершение событий | Каждые 30 секунд | Проверка event_time, установка статуса expired |
| Heartbeat | Каждые 30 секунд | Проверка WebSocket соединений, отключение мёртвых |

## Часовой пояс

Весь функционал работает в часовом поясе **Уфы (UTC+5)**. Все даты и время отображаются в местном времени.

|----------|------|-----------|

**Типы сообщений WebSocket:**
- `chat_message` — новое сообщение
- `typing` — индикатор набора текста
- `user_list` — обновление списка пользователей
- `work_notification` — уведомление о работе (created/updated/deleted/comment/edited)
- `event_notification` — уведомление о событии (created/updated/deleted/comment/edited)
- `lunch_notification` — уведомление об обеде
- `ping` — проверка соединения (сервер → клиент)

## Часто задаваемые вопросы

**Q: Почему я не могу создать событие без даты?**
A: Нужно либо выбрать дату в календаре, либо нажать кнопку "Без времени".

**Q: Почему важное событие не отображается как важное после автозавершения?**
A: При автозавершении важность автоматически снимается.

**Q: Как продлить событие?**
A: В меню действий события (кнопка ⋮) нажмите 🕐 "Изменить время" и выберите новую дату.

**Q: Почему сообщения не отправляются?**
A: Проверьте WebSocket соединение. Если страница была открыта долго, возможно произошёл разрыв. Обновите страницу.

**Q: Как посмотреть старые работы/события?**
A: Завершённые работы/события старше 30 дней автоматически архивируются и удаляются из основной таблицы.

**Q: Можно ли восстановить удалённое сообщение?**
A: Нет, удалённые данные не восстанавливаются. Рекомендуется регулярно делать бэкапы.

**Q: Как сбросить пароль администратора?**
A: Через панель управления сменить пароль может только уже залогиненный админ
(кнопка 🔑 у пользователя). Если пароль забыт полностью, нужен прямой доступ к
БД:
```bash
python -c "import hashlib; print(hashlib.sha256('НОВЫЙ_ПАРОЛЬ'.encode()).hexdigest())"
docker compose exec db psql -U postgres -d workchat -c \
  "UPDATE users SET password_hash = 'ПОЛУЧЕННЫЙ_ХЕШ' WHERE username = 'admin';"
```
Полное удаление таблицы `users` тоже приведёт к пересозданию дефолтного admin
(admin123) при следующем запуске backend — но это удалит вообще всех
пользователей, а не только сбросит пароль.

**Q: Остаётся ли пользователь залогиненным после закрытия браузера?**
A: Да, сессия хранится в localStorage и сохраняется при закрытии браузера. Разлогиниться можно только через кнопку "Выход" или очистку данных браузера.

## Бэкап и восстановление

### Создание бэкапа
Через Docker (контейнер БД называется `db`, см. `docker-compose.yml`):
```bash
docker compose exec db pg_dump -U postgres workchat > backup.sql
```

### Восстановление
```bash
docker compose exec -T db psql -U postgres workchat < backup.sql
```

### Полный бэкап
Для полного переноса на другую машину достаточно скопировать SQL-дамп
(команда выше) — сами данные в приложении хранятся только в PostgreSQL, никаких
файловых БД (SQLite и т.п.) больше не используется.

### Обслуживание: массовое удаление пользователей
`backend/cleanup_users.py` — служебный скрипт, не вызывается приложением сам.
Удаляет всех пользователей, кроме `admin`, вместе со всеми их работами,
событиями, обедами, сообщениями и комментариями. Запускать вручную и
осторожно — действие необратимо:
```bash
docker compose exec backend python cleanup_users.py
```

## Логирование

Уровни: **DEBUG** — подробная отладка, **INFO** — ключевые операции (входы,
создания, архивация), **WARNING** — предупреждения (ошибки отправки
WebSocket), **ERROR** — критические ошибки. Управляется `LOG_LEVEL` в
`backend/.env` (по умолчанию `INFO`).

В Docker-развёртывании логи смотрятся через `docker compose logs -f backend`.
Backend также пишет их в файл `backend/log.txt` внутри контейнера — но том для
него в `docker-compose.yml` не примонтирован, так что при пересоздании
контейнера (`docker compose up -d --build` и т.п.) этот файл теряется; для
постоянного хранения логов полагайтесь на `docker compose logs`, а не на файл.

## Рекомендации по эксплуатации

1. **Регулярно делайте бэкапы** базы данных PostgreSQL
2. **Не удаляйте** дефолтного пользователя admin
3. **Смените пароль** admin после первого входа
4. **Используйте стабильное** сетевое подключение для WebSocket
5. **Не открывайте** приложение в нескольких вкладках одновременно (возможны конфликты сессий)
6. **Мониторьте** `/api/health` для проверки состояния сервера
7. **Обновляйте** страницу при проблемах с подключением

## Мобильная версия

Приложение адаптивно ниже брейкпоинта 768px (Tailwind `md`):
- Сайдбар и рабочая область никогда не показываются одновременно — только
  что-то одно, переключение происходит автоматически при выборе раздела или
  собеседника/сотрудника (для разделов "Сообщения"/"Обеды" сайдбар не
  закрывается сразу — сначала нужно выбрать пользователя).
- Высота экрана считается через `100dvh` (реальный видимый вьюпорт), а не
  `100vh`, чтобы вёрстка не "прыгала" при показе/скрытии адресной строки браузера.
- На реальных тач-устройствах (не на просто узком окне десктопа — определяется
  через CSS `pointer: coarse`) поля ввода получают минимум 16px шрифта, чтобы
  iOS Safari не зумил экран при фокусе.
- Десктопная версия (сайдбар 280px, сворачиваемый) не меняется — адаптивность
  затрагивает только экраны уже 768px.
